## Логика приоритетов настроек
- 1) Явные CLI-параметры `--input-port` / `--output-port` (если переданы).
- 2) Значения из `midi_ports.json` (если файл есть и значения валидны).
- 3) Первый доступный порт из списка (fallback).
- После успешного запуска с явными параметрами — опционально сохранять эти значения в конфиг (через отдельный флаг сохранения), чтобы исключить неожиданное поведение.

## BAT-интерфейс (основной + параметризованный)
- Интерактивный режим без параметров: `configure_ports.bat`
  - меню с пунктами: показать текущие настройки, показать доступные порты, изменить input, изменить output, сохранить, запустить программу, выход;
  - валидация выбора по актуальному списку портов;
  - после изменения сразу показывает «сейчас выбрано».
- Параметризованные команды:
  - `configure_ports.bat show-config` — показать сохраненные текущие настройки (input/output).
  - `configure_ports.bat list-ports` — показать текущие `MIDI input ports` и `MIDI output ports`.
  - `configure_ports.bat set --input "<PORT_NAME>" --output "<PORT_NAME>"` — сохранить новые значения (поддержать частичное обновление).
  - `configure_ports.bat run [args...]` — запуск `main.py` с подхватом сохраненного конфига и пробросом дополнительных аргументов.

## Проверка готовности
- Запуск `main.py` без портовых параметров берет порты из конфига и показывает, какие выбраны.
- `configure_ports.bat` (без параметров) открывает интерактивное меню и позволяет изменить/сохранить выбор.
- `configure_ports.bat show-config` корректно показывает текущие сохраненные порты.
- `configure_ports.bat list-ports` выводит актуальные доступные input/output порты.
- `configure_ports.bat set ...` обновляет конфиг, и значения реально подхватываются при следующем запуске.
- README содержит короткий сценарий: интерактивная настройка -> проверка -> запуск.

## Риски и решения
- Порт может исчезнуть/переименоваться: при старте делать валидацию и понятный fallback/ошибку.
- Пробелы/спецсимволы в именах портов: в батнике использовать корректное quoting для параметров.
