# План: режим прослушивания и инструменты SDK

## Цель
Собрать короткую, практичную памятку по трем вопросам:
- как менять набор инструментов в live/stream запуске;
- какие ключевые возможности дают SDK-фреймворки;
- как получить список доступных и фактически использованных инструментов.

## 1) Изменение набора инструментов в режиме прослушивания
- Базовый набор задается при создании агента: `Agent.create(..., mcp_servers=...)`.
- На уровне конкретного запуска можно переопределить набор: `agent.send(..., mcp_servers=...)`.
- Переопределение в `send()` полностью заменяет creation-time набор для этого run (не merge).
- После `Agent.resume(...)` inline MCP-серверы нужно передавать заново, если инструменты снова нужны.
- Для local runtime дополнительные источники MCP контролируются `local.setting_sources` (`plugins`, `project`, `user`); без этого используются только inline-серверы.

## 2) Возможности SDK-фреймворков (TypeScript/Python)
- Единая модель работы: one-shot (`Agent.prompt`), долговременный агент (`Agent.create` + `agent.send`), возобновление (`Agent.resume`).
- Потоковые события: assistant/system/status/tool_call, плюс низкоуровневые дельты через `on_delta` и этапы через `on_step`.
- Контроль исполнения: `run.wait()`, `run.cancel()`, чтение состояния/результата run и conversation.
- Runtime-режимы: local и cloud; MCP-транспорты: HTTP и stdio.
- Для обработки tool payload нужно учитывать нестабильность схем `args/result` и парсить их как нестрого типизированные данные.

## 3) Получение списка инструментов
- Через CLI:
  - `agent mcp list` — список MCP-серверов.
  - `agent mcp list-tools <identifier>` — инструменты конкретного сервера.
- Через SDK-поток:
  - в `system`-сообщении доступно поле `tools` (набор инструментов для текущего run).
- Для фактически использованных инструментов:
  - анализировать `tool_call` события из `run.messages()` / `run.stream()`.

## 4) Рабочий шаблон наблюдения в stream
- После `agent.send(...)` итерировать `run.messages()`.
- На `system` сохранять/логировать `tools` как «доступный набор».
- На `tool_call` логировать `name`, `status`, при необходимости `args/result` с защитой от изменений схемы.
- Всегда завершать `run.wait()`, чтобы получить финальный статус и избежать незавершенного run-state.

- Есть единый план-файл с четкими ответами на 3 исходных вопроса.
- Зафиксированы различия между базовой конфигурацией агента и per-run переопределением.
- Добавлен практический шаблон наблюдения инструментов в stream.
